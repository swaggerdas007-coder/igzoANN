# data_cleaned_2 — one best, positive-VT device per geometry

An even stricter cut than `data_cleaned/`: instead of keeping every device
replicate that passes QC, this folder keeps exactly **one** device per
(W, L) geometry — the best-scoring device whose linear AND saturation
curves both turn on at a positive gate voltage — for each of the three
sweep kinds.

Generated by `scripts/select_best_devices.py` (built on top of
`scripts/clean_transistor_curves.py`'s QC). Regenerate with:

```
python scripts/select_best_devices.py
python scripts/plot_best_devices.py
```

## Why one device, and why positive VT

`data_cleaned/` concatenates every device replicate that passes QC for a
given (W, L). But different replicates are different physical devices with
their own threshold-voltage (VT) and mobility variation, and the model
only ever sees `(VG, VD, W, L)` — it has no "device" input to tell them
apart. Mixing several devices' curves under one (W, L) label teaches the
model contradictory examples: the same input, different device-dependent
output. Picking a single representative device per geometry removes that
ambiguity.

On top of that, this wafer shows a systematic threshold-voltage split by
die position: `bot2` (and occasionally another site) consistently turns on
at VG > 0, while most other sites turn on at a negative or near-zero VG.
Preferring the positive-VT device keeps every geometry's transfer curve
qualitatively consistent (same turn-on sign, same off-state definition
over VG < 0) instead of an arbitrary mix of positive- and negative-VT
devices from one geometry to the next.

## What's here

For each of the 19 (W, L) geometries, exactly one file per sweep kind:

- `W{W}_L{L}_linear_best.csv` — Id-Vg transfer sweep, VD=0.1V
- `W{W}_L{L}_saturation_best.csv` — Id-Vg transfer sweep, VD=5V
- `W{W}_L{L}_output_best.csv` — Id-Vd output curve family

As before, `linear`/`saturation` are the forward-only VG sweep restricted
to VG in [-2, 5] (no return leg, no off-state-floor tail below -2V).

`merged_ann_dataset.csv` combines all three cleaned sweep kinds — same
columns/shape as `data_cleaned/merged_ann_dataset.csv` — but from just the
one chosen device per geometry (13,357 rows vs. `data_cleaned/`'s 39,368).

## How the best device was chosen

1. Only devices that already pass the `data_cleaned/` three-sweep QC
   (on/off ratio, monotonic turn-on, off-state stability, VG ordering —
   see that folder's README) are candidates.
2. Each candidate's threshold voltage is estimated separately from its
   linear and saturation curves: the (log-interpolated) VG at which |ID|
   first rises through a fixed constant-current threshold (1e-9 A for
   linear, 1e-8 A for saturation), searched from the curve's minimum
   onward so a residual off-state wiggle right at VG=-2 can't be mistaken
   for turn-on.
3. Candidates with **both** VT_linear > 0 and VT_saturation > 0 always
   outrank candidates that don't clear that bar. Within that positive-VT
   group the more positive (VT_linear + VT_saturation) wins, which is what
   consistently selects `bot2`.
4. If a geometry has **no** positive-VT candidate at all (only `W160_L15`
   in this dataset), the pick falls back to the highest quality-score
   candidate among the (all-negative-VT) options, ignoring the VT
   ranking — see `quality_score` in `data_cleaned/`'s README.

`best_device_manifest.json` records, per geometry, the winner, its VT and
quality score, whether it met the positive-VT bar, and the same for every
runner-up candidate.

18 of 19 geometries landed on a genuinely positive-VT device — 16 of those
are `bot2`, one (`W5_L5`, whose `bot2` was already dead) is `bot1rep`. The
one exception, `W160_L15`, has no positive-VT candidate among its 4
QC-passing devices, so it falls back to `bot2` anyway (its highest-quality
device there, at VT_linear=-0.12V — closest to zero among the four and by
far the cleanest curve).
