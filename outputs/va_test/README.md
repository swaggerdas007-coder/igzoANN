# Bench test of `verilogA/ntft_full.va` + n-only differential pair study

Everything here is regenerated by:

```
python scripts/validate_va_model.py    # model vs measured + physics probes
python scripts/diffpair_sweep.py       # design-space sweep
python scripts/diffpair_report.py      # the two recommended designs
```

`src/va_model.py` parses the weights **straight out of the `.va` source** and
reproduces its forward pass, input clamping and analytic gm/gds. The analytic
derivatives agree with finite differences to 1e-9, so the Verilog-A chain rule
is correct and the Python is a faithful stand-in for a Spectre run.
`src/circuit.py` is a small Newton DC + nodal AC engine so gain and bandwidth
come out of a real solve, not a textbook formula.

Note this `.va` is **not** the same model as `verilogA/tft_ann_full_model.va`:
ID is 4-32-16-1 (vs 4-32-1) and the capacitances are one combined
`(VG,VD,W,L)` net (vs per-device VG-only nets). It is trained on
`data_cleaned/` (39k rows), not `data_cleaned_2/`.

## ID accuracy (held-out test split, seed 42, errors in decades)

| region | RMSE | MAE | p90 |
|---|---|---|---|
| all rows | 1.110 | 0.523 | 1.243 |
| ID > 1 nA | 0.796 | 0.382 | 1.073 |
| ID > 1 nA, VD >= 3 V | 0.790 | 0.387 | 1.060 |

Train/val/test are within 0.03 dec of each other — no overfitting, the model is
simply *underfit*. The measurement replicate spread is 0.22 dec (median), so
roughly 0.6 dec of the 0.8 is real model error, i.e. **~4x typical current
error in the on-state**. Per-geometry it ranges from 0.31 dec (W20/L20) to
1.62 dec (W80/L10).

C-V accuracy is good: 3.6% (CGD) / 3.8% (CGS) relative RMSE — but every
training row was at VDS = 0.

## What breaks for analog design

1. **`gds` is 5-20x too high; the output curves never saturate.** Measured
   W160/L20 at VG=3, VD=4 gives gds = 0.13 uS; the model says 2.06 uS. See
   `model_check.png`, bottom row — measured ID flattens by VDS ~ 3 V, the model
   keeps climbing to 5 V. Every ro-based gain number from this model is
   pessimistic by roughly 10x, and CMRR with it.
2. **ID(VDS=0) != 0.** A log10 output can't reach zero, so the model sources
   ~1 nA into a shorted device. Breaks switches, passgates and any circuit
   relying on D/S reciprocity.
3. **Hard clamping at the training-box edges.** Above VD = 5 V the input is
   clamped, so ID is perfectly flat and gds is *exactly* zero (infinite ro).
   Keep every device below 5 V or the results are meaningless, not merely
   inaccurate.
4. **`ddt(C*V)` is not charge conserving.** The `.va` writes
   `I(G,D) <+ ddt(cgd*V(G,D))` with bias-dependent `cgd`. What the simulator
   sees is `dQ/dV = C + V*dC/dV`, which differs from `C` by up to **303%** at
   the turn-on knee. A charge-based `Q = integral(C dV)` formulation would fix it.
5. **Invented VDS dependence in the caps.** CGD changes 22% between VD = 0 and
   VD = 5 although no training row had VDS != 0.
6. **Capacitance geometry coverage is 4 points** — (20,20), (40,20), (160,15),
   (160,20) um. L = 5 and L = 10 are extrapolation, and the cap-vs-VG knee
   moves erratically there (Cgs+Cgd on W160/L20 jumps 2.3 pF -> 10.4 pF between
   VG = 0.5 and 1.0 V).
7. Minor doc nit: the header says the cap target is `pF/um^2`, but the code's
   `* 1.0e-3` factor means it is really **fF/um^2**. The code is right (3.6%
   vs measured); the comment is off by 1000x.

Clean passes: monotonic in VG over the whole on-region (the 70 wiggles are all
in the ~2.5 pA leakage floor), monotonic in VD, gm/gds >= 0 essentially
everywhere (0.2% of on-region points have a marginally negative gds, vs 4.6%
for the older model in `outputs/metrics.json`), sensible W and L scaling, and
exact analytic derivatives.

## Device figures of merit (from the model, VD = 3 V)

- **gm/ID peaks at only ~3-5 /V** (vs 25-38 for a MOSFET) — a-IGZO's large
  subthreshold swing. This caps the gain of *any* single stage at roughly
  `(gm/ID) x V_swing`, i.e. ~20-25 dB with a full-rail resistive drop.
- **f_T is 100 kHz - 5 MHz.** The gate overlap capacitance is enormous:
  Cgs ~ Cgd ~ 5 pF on a 160x20 um device (~1.5 fF/um2, and this is *measured*,
  not a model artifact). Short L is the only lever — 160/5 gives ~5 MHz.
- Because Cgd is comparable to a 1 pF load, **the input feeds forward straight
  to the output**. Above the pole the gain stops rolling off and flattens at
  Cgd/(Cgd+CL) (visible in `diffpair_report.png` at -8.5 dB / -16 dB). The
  sweep flags these as `feedthrough_limited`.

## Differential pair

a-IGZO has no p-type device, so there is no PMOS mirror load. A top-side NMOS
is always a source follower (1/gm), so the two buildable loads are a thin-film
resistor and a diode-connected NMOS. Both were swept over geometry and bias
(`diffpair_sweep.csv`, 3087 valid points; points where any device leaves the
trained box are rejected outright). Resistive load wins on every axis.

VDD = 5 V, CL = 1 pF, tail M3 = 40/20 um.

| | **A — trusted** | **B — fast** |
|---|---|---|
| input pair W/L | 160/15 um | 160/5 um |
| R_L | 6.7 MOhm | 808 kOhm |
| V_CM,in / V_B(tail) | 1.0 V / 1.2 V | 2.5 V / 2.0 V |
| I_tail | 0.74 uA | 2.44 uA |
| V_out (CM) | 2.54 V | 4.01 V |
| gm (M1) | 1.98 uS | 5.25 uS |
| **Av** | **12.5 (21.9 dB)** | **4.1 (12.3 dB)** |
| **f_-3dB** | **15.7 kHz** | **171 kHz** |
| **GBW** | **197 kHz** | **704 kHz** |
| power | 3.7 uW | 12.2 uW |
| CMRR | 16 dB | 28 dB |
| slew rate | 0.74 V/us | 2.44 V/us |
| linear input range (<10% compression) | +/-0.10 V | +/-0.20 V |

Design A uses only (W,L) points the C-V nets were trained on, so its bandwidth
is backed by measured capacitance. Design B's L = 5 um input pair extrapolates
the capacitance — treat its bandwidth as indicative.

**Operating-point rules that fell out of the sweep**

- Bias the input pair at **gm/ID ~ 4-5 /V**, which here means V_GS - V_tail
  ~ 0.3-0.5 V and I_D of a few hundred nA to a few uA. Pushing current harder
  buys gm sub-linearly and costs gds quadratically.
- **Put the drop across R_L, not across the device**: Av = (gm/ID) x I_D x R_L,
  so gain is set by the resistor drop. 2.5 V of drop at V_CM,out = 2.5 V is the
  sweet spot; more than that pushes M1 out of saturation.
- **Keep V_CM,in low (0.8-1.2 V)** for gain, high (2-2.5 V) for bandwidth and
  CMRR. The two genuinely trade off.
- **Short L on the input pair** is the only real bandwidth lever (L 20 -> 5 um
  is ~4x GBW); long L on the tail device is the only real CMRR lever.
- Gain is capped near **22 dB per stage**. For more, cascade, or use a
  bootstrapped load — but this model cannot predict a bootstrapped load's gain,
  because that gain is set entirely by the `gds` it gets wrong (defect 1).

The 16 dB CMRR on design A is a model artifact of that same defect: CMRR ~
2 gm1 ro_tail, and ro_tail is understated ~16x, so expect ~20 dB better in
silicon. Longer tail L or a cascoded tail is still the right fix.

## Bottom line

The model is **usable for gm-driven design** (biasing, gm/ID, bandwidth,
resistive- and diode-load gain) and **not usable for ro-driven design**
(cascodes, current mirrors, bootstrapped loads, CMRR, PSRR). Worth retraining
with: output-conductance weighting or a gds penalty in the loss, VDS-swept C-V
data, more (W,L) points for the capacitance nets, a charge-based cap
formulation, and an ID formulation that goes to zero at VDS = 0.
